# Семантический поиск товаров по текстовому запросу (q2i)

MVP системы поиска товаров по каталогу CalmFruits: сравнение лексического (TF-IDF) и семантического (эмбеддинги) подходов, несколько экспериментов по улучшению семантического поиска, оценка качества на исторической разметке релевантности, трекинг экспериментов в MLflow, рекомендация бизнесу о целесообразности внедрения векторного поиска.

## Структура репозитория

```
.
├── semantic_search_project.ipynb        # основной ноутбук: EDA, пайплайн, эксперименты, MLflow, выводы
├── semantic_search_project_workbook.md  # рабочий документ: заметки, решения, результаты
├── check_mlflow.py                      # скрипт проверки логирования экспериментов в MLflow
├── baseline_metrics.csv                 # сводная таблица метрик базовых решений (неделя 2)
├── experiments_metrics.csv              # сводная таблица метрик экспериментов 1-3 (неделя 3)
├── final_test_metrics.csv               # метрики финального прогона на test
├── golden_set_train.json                # копия golden-сета (train), также логируется в MLflow как артефакт
├── golden_set_test.json                 # копия golden-сета (test)
├── summary_*.csv / per_query_*.csv      # таблицы метрик по каждому run (сводная и по запросам), сохраняются локально всегда и дополнительно логируются в MLflow как артефакты, если сервис доступен
├── requirements.txt                     # зависимости проекта
├── .env                                 # ключи доступа к S3 и MLflow (не в репозитории, см. ниже)
└── .gitignore
```

Данные (`.parquet`) и посчитанные эмбеддинги (`.npy`) не хранятся в репозитории — они скачиваются/пересчитываются при выполнении ноутбука.

## Что сделано

- **EDA (неделя 1):** отбор категорий «Одежда»/«Обувь» (единственные с разметкой), анализ пропусков, распределения категорий, длины текстов, проверка связности данных, распределение оценок релевантности.
- **Подготовка данных (неделя 2):** дедупликация каталога по `imt_id`, отсев карточек без текста, очистка описаний, сборка единого текста `product_text` (название + категория + описание + цвет).
- **Базовое сравнение (неделя 2):** `search_lexical` (TF-IDF + косинусная близость) против `search_semantic` (эмбеддинги `paraphrase-multilingual-MiniLM-L12-v2`) — лексический baseline превзошёл выбранную семантическую модель по всем метрикам (NDCG@10: 0.45 против 0.15).
- **Эксперименты по улучшению (неделя 3):**
  - замена модели эмбеддингов на retrieval-ориентированную `intfloat/multilingual-e5-base` (эксперимент 1) — заметно улучшила результат и превзошла лексический поиск (NDCG@10: 0.49 против 0.45);
  - гибрид через Reciprocal Rank Fusion (эксперимент 2) — небольшой прирост по NDCG@10, но заметная просадка точности в топе (Precision@1, MRR@10), признан не оправданным;
  - взвешенный гибрид 85% e5 / 15% лексика (эксперимент 3) — эффект в пределах статистического шума.
- Итоговая выбранная конфигурация — чистый `search_semantic_e5` (модель `intfloat/multilingual-e5-base`, без гибридизации).
- **Финальный тест** (один прогон на `queries_synthetic_test.parquet`, 300 запросов): NDCG@10 = 0.491, подтверждает устойчивость результата (train/val NDCG@10 = 0.493); на том же test-сплите лексический baseline даёт NDCG@10 = 0.428.
- **Трекинг экспериментов в MLflow:** 6 прогонов (`lexical_tfidf`, `semantic_minilm_baseline`, `semantic_e5_base`, `hybrid_rrf`, `hybrid_weighted`, `semantic_e5_base_FINAL_TEST`, `lexical_tfidf_FINAL_TEST`) с обязательными параметрами/метриками и артефактами; проверено `check_mlflow.py`. Логирование устойчиво к недоступности сервиса MLflow: `summary_*.csv`/`per_query_*.csv` всегда сохраняются локально, а сам прогон в MLflow логируется только если сервис отвечает.
- Подробный разбор всех решений, гипотез, качественный анализ ошибок и рекомендация бизнесу — в `semantic_search_project_workbook.md`, разделы 2.6, 3, 4, 5.
- В `semantic_search_project.ipynb` сохранены исходные комментарии ревьюера (цветные блоки) вместе с ответами на них, чтобы было легче сверяться по ревью.

## Как воспроизвести

### 1. Требования к окружению

- Python 3.10
- Файл `requirements.txt` в корне репозитория

### 2. Установка зависимостей

Рекомендуется отдельное виртуальное окружение (например, через conda):

```
conda create -n semsearch python=3.10 -y
conda activate semsearch
pip install -r requirements.txt
```

### 3. Доступ к данным и MLflow

Данные лежат в S3-бакете (Yandex Cloud). Создайте в корне репозитория файл `.env` (не коммитится, добавлен в `.gitignore`) со своими ключами:

```
S3_ACCESS_KEY=<ваш access key>
S3_SECRET_KEY=<ваш secret key>
MLFLOW_TRACKING_URI=<адрес вашего MLflow-сервера>
MLFLOW_TRACKING_USERNAME=<логин>
MLFLOW_TRACKING_PASSWORD=<пароль>
```

Ноутбук скачивает нужные `.parquet`-файлы автоматически при первом запуске (и переиспользует их при повторных запусках, если файлы уже есть локально). Для логирования артефактов в MLflow (шаг с `mlflow.log_artifact`) ключи `S3_ACCESS_KEY`/`S3_SECRET_KEY` дополнительно пробрасываются в стандартные переменные `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` прямо в ноутбуке — отдельно ничего прописывать не нужно.

Если сервис MLflow временно недоступен (например, отдаёт `503`), ноутбук не падает: подключение к нему обёрнуто в `try/except`, а все метрики (`summary_*.csv`, `per_query_*.csv`) при этом всё равно сохраняются локально — логирование в сам MLflow в этом случае просто пропускается с соответствующим сообщением в выводе.

### 4. Запуск

Откройте `semantic_search_project.ipynb` в Jupyter или VS Code, выберите ядро с установленными зависимостями и выполните все ячейки по порядку сверху вниз (Restart Kernel → Run All).

Расчёт эмбеддингов каталога (4 256 карточек) моделью `intfloat/multilingual-e5-base` занимает около 1–2 минут на CPU; результат кешируется в `catalog_embeddings_e5.npy` и не пересчитывается повторно.

### 5. Проверка логирования экспериментов (недели 3–4)

```
python check_mlflow.py semantic_search_calmfruits --env-file .env
```

## Известные особенности окружения

При установке `sentence-transformers`/`torch`/`numpy` в связке с Python 3.10 на macOS (Intel) встречается конфликт версий. Рабочая комбинация, использованная в проекте: `torch==2.2.2`, `sentence-transformers<4`, `numpy<2`. Также для загрузки артефактов MLflow в S3 нужны совместимые версии `boto3`/`botocore` (конфликтуют с `aiobotocore`, который использует `s3fs`) — рабочая комбинация: `boto3==1.39.8`, `botocore==1.39.8`. Если ставите зависимости с нуля по `requirements.txt`, все эти версии уже зафиксированы.

Сервис MLflow курса периодически отдаёт `503 Service Temporarily Unavailable` (известная проблема инфраструктуры курса, не связана с кодом проекта) — см. раздел про доступ к MLflow выше.

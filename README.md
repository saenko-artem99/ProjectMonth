# Семантический поиск товаров по текстовому запросу (q2i)

MVP системы поиска товаров по каталогу CalmFruits: сравнение лексического (TF-IDF)
и семантического (эмбеддинги) подходов, оценка качества на исторической разметке
релевантности, рекомендация бизнесу о целесообразности внедрения векторного поиска.

## Структура репозитория

```
.
├── semantic_search_project.ipynb   # основной ноутбук: EDA, пайплайн, эксперименты, выводы
├── semantic_search_project_workbook.md  # рабочий документ: заметки, решения, результаты
├── check_mlflow.py                 # скрипт проверки логирования экспериментов в MLflow
├── baseline_metrics.csv            # сводная таблица метрик базовых решений (неделя 2)
├── requirements.txt                # зависимости проекта
├── .env                            # ключи доступа к S3 (не в репозитории, см. ниже)
└── .gitignore
```

Данные (`.parquet`) и посчитанные эмбеддинги (`.npy`) не хранятся в репозитории —
они скачиваются/пересчитываются при выполнении ноутбука.

## Что сделано

- **EDA** (неделя 1): отбор категорий «Одежда»/«Обувь» (единственные с разметкой),
  анализ пропусков, распределения категорий, длины текстов, проверка связности
  данных, распределение оценок релевантности.
- **Подготовка данных** (неделя 2): дедупликация каталога по `imt_id`, отсев карточек
  без текста, очистка описаний, сборка единого текста `product_text`.
- **Два поисковых движка с единым интерфейсом**: `search_lexical` (TF-IDF + косинусная
  близость) и `search_semantic` (эмбеддинги `paraphrase-multilingual-MiniLM-L12-v2`).
- **Оценка качества**: Precision@K, Recall@K, HitRate@K, MRR, NDCG@K на каталоге
  оценки (`wb_products_dedup.parquet`, 4 256 карточек), K ∈ {1, 3, 5, 10}.
- **Ключевой результат базового сравнения**: лексический baseline превосходит
  выбранную семантическую модель по всем метрикам (NDCG@10: 0.43 против 0.15) —
  подробный разбор в `semantic_search_project_workbook.md`, раздел 2.6.

## Как воспроизвести

### 1. Требования к окружению

- Python 3.10
- Файл `requirements.txt` в корне репозитория

### 2. Установка зависимостей

Рекомендуется отдельное виртуальное окружение (например, через conda):

```bash
conda create -n semsearch python=3.10 -y
conda activate semsearch
pip install -r requirements.txt
```

### 3. Доступ к данным

Данные лежат в S3-бакете `s3-ds-source` (Yandex Cloud). Создайте в корне репозитория
файл `.env` (не коммитится, добавлен в `.gitignore`) со своими ключами:

```
S3_ACCESS_KEY=<ваш access key>
S3_SECRET_KEY=<ваш secret key>
```

Ноутбук скачивает нужные `.parquet`-файлы автоматически при первом запуске
(и переиспользует их при повторных запусках, если файлы уже есть локально).

### 4. Запуск

Откройте `semantic_search_project.ipynb` в Jupyter или VS Code, выберите ядро
с установленными зависимостями и выполните все ячейки по порядку сверху вниз
(Restart Kernel → Run All).

Первый расчёт эмбеддингов каталога (4 256 карточек) с помощью модели
`paraphrase-multilingual-MiniLM-L12-v2` занимает около 20–30 секунд на CPU;
результат кешируется в `catalog_embeddings.npy` и не пересчитывается повторно.

### 5. Проверка логирования экспериментов (недели 3–4)

```bash
python check_mlflow.py <название эксперимента> --env-file ../.env
```

## Известные особенности окружения

При установке `sentence-transformers`/`torch`/`numpy` в связке с Python 3.10 на
macOS (Intel) встречается конфликт версий. Рабочая комбинация, использованная
в проекте: `torch==2.2.2`, `sentence-transformers<4`, `numpy<2`. Если ставите
зависимости с нуля по `requirements.txt`, эта комбинация уже зафиксирована.
